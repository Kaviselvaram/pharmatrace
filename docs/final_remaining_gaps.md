## 2. Documented Environmental & Hardware Limitations

### A. Simulated Edge Hardware vs. Physical Microcontrollers
- **Current Implementation:** Telemetry is generated by `TransitSimulator` (`backend/app/engine/simulator.py`), a deterministic thermodynamic engine modeling heat transfer, compressor hysteresis, and GPS waypoints. Packets are cryptographically signed using `eth_account.Account.sign_message`.
- **Limitation:** Readings originate from mathematical software simulation rather than physical Dallas Semiconductor / Maxim Integrated DS18B20 digital thermometers or physical CAN bus vehicle interfaces.
- **Production Roadmap:** Integrate real embedded microcontrollers (e.g. ESP32-WROOM-32 or Raspberry Pi Compute Module 4 with ATECC608A Secure Element) communicating over cellular NB-IoT/LTE-M via authenticated TLS 1.3 or CoAP.

### B. Local Cancun EVM vs. Public Layer 1 / Layer 2 Mainnets
- **Current Implementation:** Deployed to a local Hardhat standalone EVM node running on port `8546` with 0-second block latency and local deterministic pre-funded accounts.
- **Limitation:** Does not experience public network gas volatility, EIP-1559 base fee surges, mempool front-running, or 12-second block reorganizations typical of Ethereum Mainnet or Polygon PoS.
- **Production Roadmap:** Deploy contracts to an enterprise Layer 2 rollup (e.g. Arbitrum One, Optimism, or Base) or an authorized private consortium ledger (Hyperledger Besu / Quorum) configured with IBFT 2.0 consensus for zero transaction gas overhead.

### C. Regulatory Certification Status
- **Current Implementation:** Algorithmic compliance reports are generated according to the electronic record standards of FDA 21 CFR Part 11 and CDSCO WHO Good Distribution Practices (GDP).
- **Limitation:** This platform has not undergone formal third-party software validation (CSV) or audit by the US Food and Drug Administration or CDSCO regulatory bodies.
- **Production Roadmap:** Perform formal GAMP 5 computer systems validation and IQ/OQ/PQ qualification protocols.

### D. Single-Node Relational Database Backup
- **Current Implementation:** SQLite 3 database (`data/infosecproj.db`) with WAL mode enabled.
- **Limitation:** While robust for local demonstrations and enterprise single-node hosting, SQLite lacks distributed multi-master replication across geographical regions.
- **Production Roadmap:** Migrate SQLAlchemy connection string to a distributed high-availability PostgreSQL 16 cluster with streaming replication and automated Point-in-Time Recovery (PITR).

## 3. Summary of Known Non-Blocker Observations

1. **Leaflet Tile Connectivity:** Map rendering in offline air-gapped environments gracefully falls back to local vector grid tracks if public OpenStreetMap tiles cannot be resolved.
2. **Hardhat Log File Volume:** Prolonged simulation runs generate verbose log output in `.hardhat.log`. A production daemon setup should implement standard logrotate policies.
3. **Browser Audio Notifications:** Toasts provide visible interactive feedback; audio chimes for critical excursions depend on user browser media autoplay permissions.
