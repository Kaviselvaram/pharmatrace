# ADR-003: Local EVM Ledger & Hardhat Toolchain
- **Status**: ACCEPTED
- **Context**: The framework requires a decentralized ledger for immutable state and cryptographic verification. Deploying solely to public testnets risks rate limits, faucet outages, or slow block times during live demos.
- **Decision**: Standardize on **Solidity 0.8.28** with a local **Hardhat EVM Network** (`http://127.0.0.1:8545`).
- **Consequences**:
  - Instant transaction mining ($<100\text{ms}$).
  - Unlimited test ETH across 20 pre-funded accounts.
  - Zero economic cost.
  - Test suites can be executed offline in CI/CD without network dependencies.

# ADR-004: Hybrid Storage Strategy (On-Chain Commitments + Off-Chain Caching)
- **Status**: ACCEPTED
- **Context**: High-frequency environmental sensors generate readings every 2–5 seconds. Storing all raw telemetry directly on the EVM causes extreme state bloat and prohibitive gas costs.
- **Decision**: Adopt a **hybrid model**:
  - High-frequency time-series telemetry is cached in an off-chain SQLite database.
  - Key state changes (Genesis, Custody Handover, Periodic Merkle/Hash Commitments, Threshold Breaches, Quarantine, and Replenishment) are committed on-chain.
- **Consequences**:
  - Directly implements the 2025 literature recommendation from the project presentation.
  - Balances sub-second UI responsiveness with cryptographic auditability.

# ADR-005: Dual AI Strategy (Local ML + Free LLM Auditor)
- **Status**: ACCEPTED
- **Context**: AI should solve genuine domain challenges without incurring paid API bills.
- **Decision**:
  - Use **Scikit-learn** locally for continuous thermal degradation rate prediction ($dT/dt$).
  - Use **Google Gemini 1.5 Flash (Free Tier)** for generating human-readable 21 CFR Part 11 compliance summaries, backed by an offline Jinja2 markdown template fallback.
- **Consequences**:
  - 100% functionality even when completely disconnected from the internet.
  - Zero recurring API expenses.

# ADR-006: Zero-Cost Local-First Deployment (Docker Compose)
- **Status**: ACCEPTED
- **Context**: The prototype must function flawlessly during evaluation without relying on unstable venue Wi-Fi or third-party cloud outages.
- **Decision**: Package the entire stack into a self-contained **Docker Compose** system that starts the EVM, Backend, and Frontend with a single command (`docker compose up`).
- **Consequences**:
  - Reproducible demo environment across any student or evaluator laptop.
  - Zero ongoing cloud infrastructure fees.
